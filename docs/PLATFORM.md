# A3 Virtual School — Platform Reference

Adaptive Algebra 1 virtual school. Deterministic mastery and routing engines
in `/lib`; LLM used only in the bounded AI-tutor seam. Supabase-ready behind
a repository interface (`types/repository.ts`), currently backed by
`InMemoryRepository` (process-local). Target: accreditation-ready (Cognia
style) and NCAA nontraditional-course compliant for the first course.

## 2. Curriculum Graph and JSON Import

**Source of truth:** `data/algebra1-graph.json`

Do not edit this file without a mr-kahn APPROVE verdict (CLAUDE.md gate).

### Schema (top-level keys)

| Key | Type | Description |
|-----|------|-------------|
| `schema` | `CourseSchema` | version, course name, sports list, phases descriptor |
| `domains` | `Domain[]` | 7 domains, each with `id`, `label`, `tier` |
| `misconceptionRegistry` | `MisconceptionRegistryEntry[]` | canonical tag list |
| `nodes` | `SkillNode[]` | 74 skill nodes |
| `edges` | `SkillEdge[]` | 114 directed prerequisite edges (`from → to`) |

### SkillNode fields

```
id           string       e.g. "ALG-F01"
title        string
domain       string       matches a Domain.id
tier         number       must equal the domain's tier (validator-enforced)
prereqs      string[]     source of truth; edges[] must mirror exactly
standards    { ccss: string[]; state: string | null }
objective    string       one-sentence learning objective
misconceptionTags  string[]  references misconceptionRegistry entries
visual       "coordinate" | "numberline" | "balance" | "table" | "area-model" | null
contextHooks Record<Sport, string>  one hook per sport including "neutral"
workedExamples  WorkedExample[]     title + steps[]{prompt, reveal}
problems     { p1: ProblemTemplate[]; p2: ProblemTemplate[]; p3: ProblemTemplate[] }
```

### Loading and validation

`data/algebra1-graph.json` is imported at server startup (InMemoryRepository
constructor or equivalent). `lib/validation/validateGraph` runs on the raw
JSON and throws if any error-severity issue is found. The Graph Inspector at
`/dev/graph` exposes the live validation report.

## 3. Validation (lib/validation)

`validateGraph(raw: unknown): ValidationReport` runs 11 rule codes:

| Code | What it checks |
|------|---------------|
| `SCHEMA` | top-level shape, required keys, domain/registry entry shape |
| `DUPLICATE_ID` | unique node ids |
| `INVALID_EDGE` | both `from` and `to` reference known node ids |
| `EDGE_PREREQ_MISMATCH` | edges[] are the mirror of prereqs[]; no extras, no omissions |
| `ORPHAN` | non-root nodes have ≥ 1 incoming edge |
| `CYCLE` | no directed cycle (Kahn DFS) |
| `MISSING_STANDARDS` | each node has ≥ 1 CCSS code |
| `MISSING_HOOK` | each node has all 7 contextHooks populated |
| `PROBLEM_MISMATCH` | each phase bank has ≥ 1 problem per sport (for p1/p2) or ≥ 1 neutral (for p3) |
| `TIER_MISMATCH` | node.tier equals its domain's tier |
| `UNKNOWN_MISCONCEPTION_TAG` | misconceptionTags reference only registry entries |

**prereqs-as-source-of-truth rule:** validator builds edges from prereqs[];
the edges[] array must mirror exactly (no extra, no missing edges). If they
diverge the validator reports `EDGE_PREREQ_MISMATCH` errors.

## 4. Mastery Engine (lib/mastery-engine)

All tuning lives in the single `MASTERY_CONFIG` object. **Any change to any
value is a Matt human checkpoint** (CLAUDE.md: mastery model weights / status
thresholds). `ENGINE_VERSION = "1.0.0"` is stamped on every proposed
`MasteryUpdate` and must be bumped on any config or logic change.

### Score blend (undecayed base)

```
baseScore = clamp01(
  0.50 × recentAcc     (geometrically weighted, most-recent highest)
+ 0.20 × overallAcc    (correct / attempts)
+ 0.15 × consistency   (1 − normalized variance of recent window)
+ 0.15 × (1 − hintRate)
)
```

Decayed score: `baseScore × (floor + (1 − floor) × 2^(−days / halfLifeDays))`
where `floor = 0.4`, `halfLifeDays = 21`.

### Status ladder (evaluated in order per node)

1. **Ever-mastered path** (`masteredAt ≠ null`) — exempt from
   `prerequisite_gap` entirely. Stays `mastered` (sticky) unless a review
   trigger fires:
   - **Decay branch:** decayed score < `reviewTrigger (0.75)` AND ≥ 1 full day
     elapsed since `lastAttemptAt`. Under one day the branch is INERT.
   - **Attempt-evidence branch:** `recent.length ≥ lockConfirm (2)` AND
     `recentAcc < recentDip (0.6)`. Fires at any elapsed time.
   - Both branches → `needs_review`. Only way back: `restore` (recent ≥ 2,
     `recentAcc ≥ 0.8`, at least one recent correct Phase-3 attempt).
   - `masteredAt` is refreshed on restoration.
2. **Not-ever-mastered: gap override.** `prerequisite_gap` if any prereq
   has `lockingGap = true`.
3. **Fresh mastery:** score ≥ `mastered (0.85)` AND `transfer === true` AND
   `attempts ≥ minAttempts.mastered (3)`.
4. **Evidence bands:** `unknown` (0 attempts) → `introduced` (< 3 attempts) →
   `developing` (score < 0.7) → `near_mastery` (score ≥ 0.7).

### lockingGap rule

A prerequisite result locks its dependents when:
- Not ever-mastered: `score < prereqGate (0.7)`.
- Ever-mastered: `recent.length ≥ lockConfirm (2)` AND (if exactly 2: both
  incorrect; else `recentAcc < recentDip (0.6)`). Pure decay on an
  ever-mastered prereq never locks — only recent attempt evidence does.

### computeMasteryAll + proposedUpdates

`computeMasteryAll(studentId, states, graph, nowIso)` iterates in topological
order (Kahn), computes `MasteryResult` for every node, and returns:
- `results: Record<string, MasteryResult>` — the current snapshot.
- `proposedUpdates: NewMasteryUpdate[]` — one per node present in `states`
  whose computed status differs from the persisted status (trigger `"attempt"`
  or `"decay"`).

Callers append the proposed updates to the immutable log and call
`setSkillState` with the updated `StudentSkillState`. The engine never mutates.

### Sticky mastery + masteredAt

Diagnostic credit sets `masteredAt` directly via `creditFromDiagnostic` /
`propagateDiagnosticCredit` — no attempts floor applies. The acceleration path
enters the sticky (ever-mastered) branch with zero attempts and stays there.

### Append-only evidence

Every attempt and mastery change is an immutable row:
- `StudentAttempt` — attempt, time, hints, response, phase, sport, source,
  sessionId, misconceptionTags, isProbe, attemptId reference.
- `MasteryUpdate` — trigger (`attempt` | `decay` | `diagnostic` |
  `credit-propagation`), prev/new status, prev/new mastery, prev/new phase,
  reason, engineVersion, sessionId.

`source` and `sessionId` are stamped for audit provenance and **never enter
engine math** (mastery/phase/transfer/routing are source-agnostic).

## 5. Three-Phase Progression

### Phases

| Phase | Label | Context |
|-------|-------|---------|
| P1 | Sports context | Problems use the student's chosen sport as context |
| P2 | Blended | Sport + neutral problems mixed |
| P3 | Neutral transfer | All problems in standard academic notation |

**Mastery requires demonstrated P3 neutral transfer. No exceptions.**
`computeTransfer` in `lib/problem-engine` counts only Phase-3 correct attempts
in the recent window (window 5, required 2).

Phase advance is computed by `advancePhase` in `lib/problem-engine`:
accuracy ≥ 0.80 over ≥ 4 attempts in the current phase, excluding probe slots.

### Diagnostic (lib/diagnostic-engine)

Depth-anchored adaptive placement; ≤ 15 items (`DIAGNOSTIC_CONFIG.maxItems`).

- **Neutral P3 gate (mr-kahn #3):** every item is a neutral Phase-3 problem.
  Credit is granted only on a correct neutral-p3 response.
- **Probeability gate (mr-kahn #2):** a node is probeable only if its p3 bank
  has ≥ 1 neutral problem. Domains with no probeable nodes (currently Systems,
  Exponents & Polynomials, Quadratics, Data) are never probed; their cluster
  estimate reports `confidence: "unknown"` / `unestimated: true`.
- **Depth metric:** `prereqDepthWithinDomain` — longest same-domain prereq
  chain back to a domain root. Never `tier` (which is domain-level; useless
  for within-domain depth).
- **Anchor:** one per probeable domain; the deepest probeable node (tie-break:
  domain tier asc, then skillId lex). Served before any descent or confirmation.
- **Confirmation probe (mr-kahn #4):** if crediting one correct answer would
  credit ancestry crossing a domain boundary OR ≥ `creditDepthConfirm (4)`
  ancestors, one confirming probe on a mid-depth ancestor is served first.
  Correct confirm → full chain credited (both probed: "high"; inferred
  between: "medium"). Incorrect confirm → nothing above the confirm point is
  credited; walk descends from the confirm node.
- **Retake:** strictly additive — only ever credits MORE skills. Never revokes
  prior diagnostic credit (sticky mastery + lockConfirm floor guarantee this).
- **Determinism:** item sequence is a pure function of (graph, config,
  responses). Internally every API replays the response list from scratch.
- **Session progress:** `0.5 × (localized-domains fraction) + 0.5 × (budget
  used)`. Monotonic, never a question count.

After the diagnostic, `creditFromDiagnostic` / `propagateDiagnosticCredit`
(in `lib/mastery-engine`) set `masteredAt` on demonstrated and inferred nodes.
`diagnosticTaken(attempts)` derives completion from the append-only attempt
log (any row with `source === "diagnostic"`). `diagnosticCreditedSkills(updates)`
derives the credited skill set from the update log.

### Adaptive router (lib/adaptive-router)

`recommend(graph, results, states, justCredited?)` returns one
`AdaptiveRecommendation`:

| Kind | When |
|------|------|
| `complete` | All nodes mastered |
| `review` | Any `needs_review` exists (worst first: lowest score, domain tier, skillId) |
| `remediate` | Frontier top candidate blocks ≥ 1 dependent AND attempt evidence exists |
| `accelerate` | `justCredited` skill is a transitive prereq of the frontier candidate |
| `continue` | Default |

Frontier = nodes not mastered whose prereqs ALL pass `lockingGap` (none lock).

### Learn → Practice → Summary loop

1. **Learn** (`/student/learn/[skillId]`): interactive lesson (manipulable +
   worked example). No persistence. Session-gate: worked example must be
   reviewed once before practice unlocks (UI gate only, not an evidence row).
2. **Practice** (`/student/practice/[skillId]`): one problem at a time.
   Each submit calls the `submitPractice` server action → `practiceSession`
   in `lib/practice-session` → appends `StudentAttempt`, runs
   `computeMasteryAll`, appends `MasteryUpdate` rows, updates `StudentSkillState`.
   Feedback shows correct/not-quite + why-assembly (never raw engine internals).
   Probe slots (N+1-phase stretches) are excluded from phase-advance math.
3. **Summary** (`/student/summary`): session outcome, mastery change, next step.

## 6. Compliance Posture

Build for compliance now; certify later after the pre-launch gate list closes.

### Evidence trail

Every attempt, hint, time-on-task, and mastery/status/phase transition is an
immutable row (`student_attempts` + `mastery_updates`). Insert-only enforcement
uses two independent mechanisms in the migration:
(a) `REVOKE UPDATE, DELETE` from application roles (blocks normal paths).
(b) `BEFORE UPDATE OR DELETE` trigger that `RAISE`s (blocks any role, including
    the table owner and `SECURITY DEFINER` paths that bypass RLS).

See `docs/compliance/evidence-trail.md` for a concrete reconstruction walkthrough.

### Standards transcript (lib/transcript)

`buildTranscript(studentId, graph, states, updates)` produces a
`StudentStandardTranscript` by rolling each graph node's CCSS codes up using a
**weakest-link (conjunctive) rule**: a standard is `mastered` only if EVERY
contributing node is mastered. Never any-node, never a numeric average.

`creditTier` (`"credit-bearing"` vs `"prerequisite-review"`) is DERIVED here
from the CCSS code prefix — never authored into `data/algebra1-graph.json`.
HS conceptual-category codes (`A-`, `F-`, `N-`, `S-`, `G-`) are credit-bearing;
middle-school codes (leading digit) are prerequisite-review.

### Migration spine (supabase/migrations/0001_compliance_spine.sql)

**UNEXECUTED.** Running this migration is a Matt human checkpoint (CLAUDE.md).
Tables: `student_profiles`, `sessions`, `student_skill_states`,
`student_attempts`, `mastery_updates`, and NCAA/COPPA/FERPA stub tables
(`enrollments`, `messages`, `consent_events`, `record_access_log`).

All PKs are `uuid` (not bigint identity). Every timestamp is `timestamptz`.
RLS policies stub `student_id`/`campus_id`/`role` claims from JWT; the helper
functions exist in the migration but are inert until auth is wired.

### COPPA / FERPA / NCAA stubs

- **COPPA:** students are largely under 13. Parental consent flow is a
  placeholder. Data minimization: no third-party trackers on student surfaces.
  See `docs/compliance/privacy-checklist.md`.
- **FERPA:** student records are handled in the repository layer only; no PII
  in client bundles or logs.
- **NCAA nontraditional-course:** scope & sequence is the graph; teacher
  interaction surfaces are stubbed (`messages`, `enrollments` tables + `/dev/messages`
  placeholder). Defined course timeframe and teacher access to student work are
  architectural requirements; implementation is pending.

**No accreditation or NCAA credit claim is made until the pre-launch gate list
below is closed.**
