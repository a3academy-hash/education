# Archetype: rubric-explanation

Pairs a deterministic closed-form anchor part with a rubric-scored open-response explanation. The anchor is the item's sole gating evidence; the open part produces advisory-only misconception evidence through the free-response grading channel — the one place in the bank where an LLM reads student work.

Gold exemplars (cite only, never copy): `docs/gold-node/GOLD_NODE_RUBRICS.md` — item `ALG-L06-gold-rex-01` (§3), rubric `RUB-L06-explain` (§2), graded samples (§5.1–§5.2). The rubric contract itself is GOLD_NODE_RUBRICS §1; the transfer-battery dimension-1 gold item `ALG-L06-gold-tb-d1-01` (§4) reuses this archetype's part shape inside a gate item (archetype-transfer-battery §a.7).

## a. Construction rules

1. **The anchor part always comes first.** Every instance is exactly two parts in fixed order: part (a), a deterministic closed-form component (numeric or choice) on the same object the explanation will address; part (b), the rubric-scored open response. Grounding (RUNTIME §4): provisional state advances **only on deterministic evidence** — on grading failure the explanation is marked ungraded and the item still resolves on part (a)'s solver-checked answer, so **a standalone rubric item would stall on grading failure.** The anchor is what makes the RUNTIME §4 fallback non-degenerate (GOLD_NODE_RUBRICS §1.2 item 4), and it is this item's sole gating evidence (§d).
2. **Single ask per part.** Each part carries exactly one ask, one interrogative close. The two-part shape is a **declared deviation** from the standalone-P3 no-sub-parts rule (QUESTION_VOICE §10), required by RUNTIME §4's deterministic-anchor mandate for rubric-scored items (rex-01 authoringNote; GOLD_NODE_RUBRICS §6.2 declares it).
3. **One rubric, one eliciting prompt — elicitation honesty.** The open part's prompt is the rubric's `promptRef` target, and the rubric scores only meanings the prompt actually elicits. An element the prompt never asks for is dropped from the rubric, not scored-by-absence (the RUB-L06-transfer-d1 precedent: taxonomy §3.3 row 4 dropped because "part (b)'s prompt never elicits the subtraction-direction invariant … the ≤4-element bound is met by honest trimming, not compression"). Dropped elements keep their deterministic channel through the anchor's traps.
4. **Rubric conformance, field for field** (GOLD_NODE_RUBRICS §1): each `requiredSemantic` is one sentence of meaning — never a keyword list; paraphrase in any register counts; `canonicalAnswer` is a grading anchor only, NEVER shown to the student; `gradableRule` in the fixed class ("gradable = false only when the response is empty, off-task, or uninterpretable; a wrong-but-on-task explanation is gradable = true with low element scores"); `met = score ≥ metThreshold`.
5. **Anchor trap arming** per the standard rules: every applicable entry signature evaluated at parameterization; traps live under their generator constraints, pairwise distinct, distinct from the key, outside grading tolerance; collision matrix consulted; §2.9-class minimum-separation respected (rex-01 excludes the too-close single-point-ratio traps per that recommendation — noted, not armed).
6. **Hints never fire on the open part.** The `hintLadderRef` binds to anchor traps only. A submitted open response is graded (or queued ungraded per §d) — it is never laddered, never coached, never retried against hints. This is a binding archetype condition, not a default.
7. **Visual withheld until the whole item resolves.** The explanation must come from the student's own model, not from reading arrows and a readout off the canvas (V-GN-REX01 purpose; §e).

## b. Taxonomy interface (requirements on node taxonomies)

1. **A §3.3-style rubric element table is REQUIRED node-taxonomy supply** (TAXONOMY_TEMPLATE §4.5 row 10): the node's core-explanation required semantic elements, each annotated with the `counteredEntryIds` whose belief that element's presence contradicts. This archetype cannot instantiate on a node whose taxonomy lacks the table — the rubric object is the table formalized (RUB-L06-explain is taxonomy §3.3 row-for-row).
2. **Belief-form rewritability for element counters** (taxonomy §1 condition 1; TAXONOMY_TEMPLATE §3.2/§3.8): every entry named in a `counteredEntryIds` list must have a Definition that names a belief a missing element can raise a prior on. Output-named entries cannot be countered by a semantic element and are ineligible as counters.
3. **Closed-form signature entries + generator constraints** for the anchor's trap set (TAXONOMY_TEMPLATE §4.5 rows 1, 13) — the anchor is a standard closed-form part and makes the standard demands.
4. **Text-evidence disambiguation rules** where the anchor's numbers can land in a collision zone: the taxonomy should state how rubric-text evidence re-attributes a colliding numeric trigger (the gold pattern: a bare Δy anchor answer defaults per the collision matrix, and the §2.10-style belief "arrives through part (b)'s rubric evidence if the text shows the interval was seen but never normalized" — GOLD_NODE_RUBRICS §5.4 grading note).
5. **Advisory-evidence semantics stated** in the node's §3.3-contract restatement (TAXONOMY_TEMPLATE §5.3): a missing element raises priors on its countered tags and never activates; the node doc says so explicitly so engine behavior is defined.

## c. Voice conformance

- **Assessment register throughout** (QUESTION_VOICE §10): stem ≤48 words carrying data only, 0–2 context sentences, units attached, ask last in each part, both asks interrogative (rex-01 §6.2 measurements are the exemplar row).
- **Declared deviation:** two parts against the standalone-P3 no-sub-parts rule, per rule a.2 — declared in the entry and in every instance's authoringNote, exactly as the gold instances declare it.
- **The open ask names the demand plainly** ("Explain in two or three sentences: how … and why does the method work?") — an `explain/justify` frame; sentence-count guidance in the ask is task framing, not coaching.
- **No coaching:** the stem and anchor ask never pre-state the method, name the formula, or enumerate what a good explanation contains — the rubric's elements must be recoverable from the student's own model, not from the prompt.
- **FK band scoping:** the assessment FK 6–8 band is a ceiling over the full student-visible surface; minimal data-only stems below band are compliant by design (§11.1 row 11 ruling).

## d. Deterministic-gradability contract

- **The open part is the system's one LLM-evidence surface for scored student work.** Free-response grading (RUNTIME_TUTOR_SPEC §1.2, output schema §3.2) is the only runtime call that reads a bank item's student response, and this archetype's open part — plus the two reuses of its part shape: transfer-battery dimension-1 open parts (archetype-transfer-battery) and lesson-side worked-example self-explanation prompts (archetype-worked-example §d) — is the only content that routes there. Every other scored surface in the bank grades on the RUNTIME §6 never-LLM list item 1 solver path. (Tutor-turn suspected tags share the advisory *channel* but are conversation, not item evidence.)
- **Advisory-only, never gates** — the GOLD_NODE_RUBRICS §1.2 rule, verbatim-faithful to taxonomy §3.3: a missing element "raises the skill model's prior on the countered tags … but **never sets a tag active by itself** — active status still requires a signature hit or failed probe." A detected tag (affirmative textual evidence) is logged advisory evidence with confidence; activation stays at taxonomy §3.4 (2 signature hits, or 1 hit + failed disambiguation probe). No rubric score, element outcome, detected tag, or confidence value gates mastery, routing, or a transfer-battery pass — all on the RUNTIME §6 never-LLM list.
- **The anchor part is the item's sole gating evidence.** Part (a)'s deterministic answer-check is what provisional state consumes (RUNTIME §6 item 1); part (b) sharpens diagnosis and never decides (GOLD_NODE_RUBRICS §5.2 engine-side story is the worked demonstration).
- **Fallback = ungraded + human-review queue** (RUNTIME §4 row, unmodified): schema-invalid grade → one retry → on second failure the explanation is marked "ungraded — queued for human review"; provisional state advances on the anchor alone; the lesson never stalls.
- **`met` semantics are D4-supplied:** `met = score ≥ metThreshold` (RUNTIME §3.2 leaves `met` undefined); `metThreshold` is grader input, never echoed in output.
- **counteredEntryIds withholding (declared deviation / proposed amendment to RUNTIME §2):** `counteredEntryIds`, `scoreWeight`, `metThreshold`-aggregation, and `canonicalAnswer`-visibility are host-side; `counteredEntryIds` and `scoreWeight` are never sent to the grader (anti-bias — the grader judges element presence without knowing which beliefs an element counters or how it is weighted). RUNTIME §2's envelope example currently carries `counteredEntryIds` inside `item.rubric`; the never-sent rule is flagged as a deviation pending that amendment, not asserted compatible (GOLD_NODE_RUBRICS §1).
- **Fallback-model routing:** ≤4-element rubrics may grade on `GRADING_FALLBACK_MODEL`; 5+ elements on `RUNTIME_MODEL` only (RUNTIME §1.2).
- **Audit:** rubric scoring logged per element and sampled for human review (`new_plan/CLAUDE.md` §10); `evidenceSpan` is an exact substring of the student text or `""` for a simply-absent element (GOLD_NODE_RUBRICS §1.1).

## e. Visual spec requirements

- **Withheld-entirely convention:** nothing renders during part (a) or part (b) — the item is the assessment of the student's unaided model. The full D1-convention spec exists and is Manim-buildable, held to a single confirmation reveal after the open part submits (V-GN-REX01: "(No visual during parts (a) and (b) …)" is a legal, explicit beat).
- **Confirmation payoff staging:** on part (b) submit, the complete structure draws (plane, points, line, rise/run arrows with arithmetic labels, readout) — the student's explanation rendered back ("your sentences, drawn." caption class).
- **No nulls:** axes with label/range/gridline_every, points with labels, line description, arrows with from/to anchors and arithmetic label strings, readout — all specified even though held back.
- **Standard color conventions:** rise `--blue-on-light`, run `--green-on-light`; annotations state the hold-back rule explicitly ("held back entirely until part (b) is submitted — no scaffold may leak into the rubric-scored explanation").

## f. Interest-skinning rules

- **Rubric prompts are procedure-general — skin-independent.** The open ask names the procedure ("how do you find the slope of a line from any two points…"), not a context; it is byte-identical across any skin, and every `requiredSemantic` sentence is context-free by construction. A rubric whose elements name context quantities belongs to a transfer-battery dimension-1 item (where the changed story is the construct), not to this archetype.
- **Anchor data skins per its own archetype rules:** the anchor is a closed-form component and inherits the standard freeze for its answer type — every number, the key, all trap values and their entry IDs, and generator-constraint satisfaction FROZEN; nouns, unit labels, and personas swap (the scaffolded-multistep §f / discrimination §f contract, whichever form the anchor takes).
- **P3 instances never skinned** (phase discipline). With phaseApplicability P3-only, no instance of this archetype skins in practice; the two rules above bind any future P1/P2 exemplification.
- **`canonicalAnswer` never varies with a skin** — it is procedure-general grading-side prose.
- **§6.1 hard constraints** (INTEREST_DOMAINS) apply fatal-class to any future skinned instantiation, exactly as everywhere else in the library.
